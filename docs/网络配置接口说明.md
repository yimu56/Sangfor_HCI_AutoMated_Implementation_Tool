## 二、四个功能的完整链路

### 0. 先理解 `channelN`（聚集口 = 虚拟网线承载口）

抓包里的 `channel1..channel4` 都是 **bond 逻辑口**，在 `/cluster/network/ifaces` 里以 `type=bond` 出现：

```
channel1  members=eth2,eth3  role=["tercom","mgmt"]    ← 管理口（有管理 IP）
channel2  members=eth4,eth6  role=["business"]         ← 业务口
channel3  members=eth5,eth7  role=["vs"]               ← 存储口
channel4  members=eth8,eth9  role=[]                   ← 空闲
eth1      type=phy-iface     role=["vxlan"]            ← VXLAN 隧道承载
```

所以「配业务口 / 配存储网」本质是**把某个 channelN 绑到对应角色上**；
`freePhyIfacesOf()`（`netcfg_ui.go`）负责算出「不属于任何 bond、且无角色占用」的物理口，
供端口聚合页选成员口用。

### 1. VXLAN IP 池

```
读 : GET  /vapi/extjs/network/v1.0/vxlan-ip-pools?start=0&limit=20
     → data.vxlan_ippools[]           ← 注意列表键是 ippools（复数）
写 : POST /vapi/extjs/network/v1.0/vxlan-ip-pools        (Content-Type: application/json)
     {"vxlan_ip_pool":{"ip_range":["10.10.141.1",...],
                       "netmask":"255.255.255.0",
                       "gateway":"",
                       "node_ids":["host-xxx",...],
                       "description":""}}
     → data.vxlan_ip_pool            ← 单条键是 ip_pool（单数）+ 服务端算出的 node_ips
```

要点：

- **`ip_range` 与 `node_ids` 一一对应（按顺序分配）**，长度必须相等。界面因此要求
  「IP 数量 = 勾选节点数」，并提供「按节点数生成连续 IP」按钮（起始 IP 依次 +1）。
- 响应里的 `node_ips: [{vxlan_ip, node_id}]` 是服务端算出的映射，界面提交后回显做对账。
- `gateway` 可为 `null`（读）—— Go 侧用 `*string` 承接，否则解析报错。
- 该接口**没有任务号**，返回即创建完成。

### 2. 端口聚合（bond）

```
写 : POST /vapi/json/cluster/network/bonds               (Content-Type: form-urlencoded)
     ifaces=[{"node_id":"host-xxx",
              "bond":{"members":"eth4,eth6","mode":"lacp-layer34"},
              "vlan":{},"iface":{},"fusion":{"fusion_enable":0}}, ...]
     → data.task_id
读 : 没有独立的 bonds 查询接口 —— 聚合口信息就在 /cluster/network/ifaces 里
     （筛 type=bond 即是）
```

要点：

- `members` 是**逗号分隔的字符串**（不是数组），顺序即提交顺序。
- 一次请求可覆盖多节点（抓包里就是 6 节点一次提交），与设备页面行为一致。
- **聚合模式取值不要写死**：抓包实测值只有 `lacp-layer34`，且集群里 channel1~4 全是这个值。
  界面用**可编辑下拉**：预置 `lacp-layer34 / lacp-layer23 / active-backup / balance-xor /
  balance-rr / broadcast`，并动态并入设备现网已使用的模式，同时允许手工输入 ——
  避免因固件版本差异漏掉新模式。`lacp-layer34` 在界面上标注为「抓包实测值」。

### 3. 存储网（存储通信网口配置）

```
读  : GET  /vapi/extjs/vs/vs_config/vs_networksetting_get?add_host=0
      → data[]  每节点 {host_name, service_ip, host_alias, host_ip,
                        netmask, host_mask, nics[], vlan_id, type,
                        hoststatus, host_status, used_rdma, is_new}
校验: POST /vapi/json/vs/vs_config/vs_check_arbiter_same_netip   (form)
      change_iface_type=private & host_list=[...]        ← 与读接口同结构的数组
      → data{warn_info, warn_level}
写  : POST /vapi/extjs/vs/vs_config/vs_networksetting_set        (form)
      networksetting=[...]
      → data 是【UPID 字符串】，不是 {"task_id":...}
轮询: GET  /vapi/json/log/process?upid=<URL编码后的 UPID>
回读: GET  /vapi/extjs/vs/vs_config/is_net_config
      → type 由 NONE 变为 standard_network 即配置生效
```

要点（都是坑）：

- **`data` 直接是 UPID 字符串**：`"UPID:host-5079732de1f5:0001CB6F:...:添加主机::admin@vtp:"`。
  若按 `{"task_id":...}` 解析会直接失败。轮询前必须 `url.QueryEscape`（含中文与冒号）。
- **`change_iface_type=private` 严格照抓包原值**：抓包里没有旁证说明该字段的取值集合，
  因此代码里定义为常量 `vsChangeIfaceType` 并显式注释「取自抓包原值，不臆测」。
- `host_list` / `networksetting` 的元素必须**带上读接口返回的全部字段**
  （`host_alias`/`host_mask`/`hoststatus`/`is_new`/`type`…）。少字段设备会静默不生效。
- 同结构里同时存在 `hoststatus` 与 `host_status` 两种拼写 —— 都要带上。
- 界面把「读接口原值」与「用户改动」合并后提交：`collectVSSettings()` 里
  `cur := curByHost[r.hostName]` 就是为此。

### 4. 业务口（SDN 拓扑「物理出口」节点）

```
读  : GET  /vapi/json/cluster/network/business-ifaces[?refresh=1]
      → 扁平数组，元素自带 node_name/node_status，role 含 "business"
校验: POST /vapi/json/asan/v1.0/networks/ifacecheck            (JSON)
      {"host_eth":{"host-xxx":["channel2"],...},
       "net_type":"business_iface",
       "iface":"<拓扑节点 UUID>"}
      → data.is_access_iface
写  : POST /vapi/json/hci/sdn/ui/network-portal/nodes/action   (JSON)
      {"type":"add",
       "nodes":[{"id":"<拓扑节点 UUID>",
                 "bridge_list":"[{\"device_type\":\"evs\",
                                   \"location\":[\"host-xxx\"],
                                   \"peer_device\":{\"vlink_id\":\"channel2\",
                                                   \"device_type\":\"host\"}}, ...]"}]}
      → data.task_id
```

要点：

- **`bridge_list` 是「内层 JSON 字符串」（双层 JSON）**：外层是请求 JSON，
  内层是把 `evs → host vlink` 映射数组再序列化成的字符串。必须保持字符串形态，
  不能改成嵌套对象。
- **拓扑节点 ID 由客户端本地生成 UUIDv4**（不是服务端下发）：
  抓包里该值形如 `6d1b0e3d-05ad-412f-b3e4-508eddf01a8f`（第 3 组以 `4` 开头 = v4），
  且紧随其后的任务日志里出现「创建拓扑节点 / 创建物理出口 / 创建设备分组映射关系成功」。
  实现见 `NewUUIDv4()`，界面提供「重新生成」按钮。
- 该功能在设备上对应 **拓扑 → 物理出口**，属于 SDN 虚拟网络层，
  与 `role=["business"]` 的 bond 是两层概念（后者是虚拟网线角色，前者是拓扑绑定）。

## 三、写操作的保护设计（沿用「修改网口配置」页并加强）

每个页面统一走 5 段式，写操作前一定能看到「现网值 vs 目标值」差异：

```
读现网 → 本地校验 → 设备侧预校验 → 预览 diff → 危险确认框 → 提交 → 轮询任务 → 回读验证
```

两阶段提交（存储网 / 业务口）：

1. 点「校验并提交」→ **只在后台跑设备侧校验接口，不写入**
2. 校验结果回到 UI 线程后，把「差异表 + 校验告警」一起放进**危险操作确认框**
3. 用户点「是」才真正下发；点「否」恢复按钮并提示「已取消（未写入）」

回读验证：

- 存储网：任务完成后自动 `is_net_config` 回读，把 `type` / `is_config` 写进结果面板
- 业务口 / 端口聚合：任务完成后自动重拉 `business-ifaces` / `ifaces` 刷新现网表格
- VXLAN IP 池：创建响应即含服务端映射，直接回显 `节点 → IP` 明细

本地校验（提交前拦截，不发无效请求）：

| 页面 | 校验项 |
|---|---|
| VXLAN IP 池 | IP 数量 = 节点数；逐个 IP 合法性；IP 去重；掩码合法；网关与 IP 同网段 |
| 端口聚合 | 至少选 1 个节点；至少选 1 个成员口；模式非空 |
| 存储网 | 逐节点 IP/掩码合法；IP 全局去重；VLAN 0–4094；承载口已选 |
| 业务口 | 至少 1 个节点；承载口已选；UUID 非空 |

## 五、界面上踩到的坑（walk 相关，已修）

### 坑 1：HBox 会把控件拉得很宽

`walk` 的 `HBoxLayout` 会把多余横向空间**摊给子控件**，导致按钮/输入框被拉成一块大长条。
修法：给控件显式固定宽度（`setFixedWidth()`），并在行尾加 `HSpacer` 吸收剩余空间。

### 坑 2：VBox 会把多余纵向空间摊给"标签行"和"分组框"

表现为「一行很高、内容悬空居中」，或「分组框很高、里面大片空白」。
修法：

- 表单行 / 每节点行固定高度（`rowHeight = 26`）
- 复选框组按行数算总高（`checksPerRow = 4` 估算行数）
- 页面最后一个控件（差异文本框）**只给最小高度**，让多余空间都给它

### 坑 3：给 `GroupBox` 设固定高度会与它自身的「标题 + 边框」布局冲突

实测：`GroupBox.SetMinMaxSize({h},{h})` 后，内部内容被挤到顶部并与标题**重叠**，
6 个节点 2 行时整组内容全部不可见。**复选框组因此改为「普通 Composite + 加粗标题行」**，
不再用 GroupBox 包。

### 坑 4：`DropDownBox` 实际类型是 `*walk.ComboBox`

`walk.NewDropDownBox()` 返回 `*ComboBox`（只是 `CBS_DROPDOWNLIST` 样式），
声明成 `*walk.DropDownBox` 编译不过。取值用 `Text()`（`Model()` 返回 `interface{}`，拿不到 `Len()`）。

### 坑 5：`VSplitter` 默认 50/50 会把编辑区压扁

存储网页需要按节点数放多行控件，被压到看不见（每节点编辑行全在滚动区外）。
改为**上侧固定高度 + 下侧自适应**（`pageBody(page, topHeight)`），不再用 Splitter。
