# 深信服设备管理工具（sangfor-ifaces）GUI 版

深信服超融合设备 vapi 接口客户端 —— **Windows 原生桌面窗口程序**（Walk/Win32，Go 编写，运行时无黑框）。

> 本文档同时作为**上下文交接文档**：粘贴到全新的 AI 助手 聊天窗口后，无需任何历史记忆即可无缝继续本项目的开发与测试。

---

## 1. 一句话目标

把原命令行工具 `sangfor-ifaces`（深信服超融合设备 vapi 接口客户端）改造成 Windows 原生桌面窗口程序，包含登录、节点/网口/虚拟机/硬件查询、修改网口配置，以及 **4 类网络配置写操作（VXLAN IP 池 / 端口聚合 / 存储网 / 业务口）**，并取消运行时黑框。

## 2. 背景与上下文

- **使用场景**：运维人员在 Windows 上管理深信服超融合设备（如 `192.168.1.100`），通过逆向抓包得到的 vapi 接口协议自动登录并查询/修改配置。
- **原始形态**：`main.go` 是 1798 行纯命令行程序（交互菜单 + 脚本参数模式），用户嫌 CLI 不够直观，要求加 UI。
- **需求确认结果**：① 桌面窗口程序（否决了 Web UI 和终端 TUI）；② 功能全做，含修改网口配置；③ 修改网口**不做密码二次验证**（"先把功能加上去，后续人工验证"）；④ **直接替换**命令行模式（CLI 废弃，仅留备份）。
- **测试阶段追加约束**：曾限定只允许修改 ETH4 网口的 IP 和掩码（`allowedIface` 常量），**现已放开**：所有网口、所有字段（IP/掩码/网关/MTU/自定义名称/备注/链路模式）均可修改。
- **当前状态**：等待用户在真实设备上实测修改网口配置。

## 3. 当前状态总览

- 当前阶段：GUI 改造 + **4 类网络配置写操作**均已完成，并通过「HAR 报文回放 + mock 服务端 + 协议层 go test + GUI 无头驱动截图」四重离线验证；等待用户在真机上实测
- 完成度：约 92%（功能全部实现且离线验证通过；**真机写操作未验证**）
- 当前阻塞：无代码阻塞；依赖用户真机实测反馈
- 主要风险：① 修改网口 / 存储网 / 业务口均为高危写操作，可能导致设备断网、存储通信中断或业务不通；② 跳过密码验证属用户明确要求的临时策略，正式使用前需评估；③ 4 类新接口**只做过 HAR 回放验证，未在真机下发过**。

10. **布局坑修复**：① 表单 GridLayout 不自动排布 → 改 VBox + 每行 HBox；② ScrollView 不能包 inner → 直接用 ScrollView 当容器。
11. **刷新残留修复**：`WidgetList.Clear()` 不销毁窗口句柄、`Dispose()` 不递归 → 新增 `disposeWidgetTree` 递归销毁，刷新硬件信息不再叠加"多个窗口"。
12. **修改网口体验优化**：① 网口/链路模式下拉改用 `NewDropDownBox`（CBS_DROPDOWNLIST：不可编辑防误删，点击输入框任意位置即弹出下拉列表）；② 硬件信息页每个节点分组新增"复制本节点信息"按钮（`walk.Clipboard().SetText(hostInfoText)`，只复制当前节点）；③ 预览/提交的变更明细改为等宽对齐表格（`formatChanges` + `dispWidth` 中文宽度对齐），可读性大幅提升。
13. **截屏验证**：PrintWindow 截窗口图 + 识图，确认修改页表单、硬件页 GroupBox、登录栏均正常渲染。
14. **4 类网络配置写操作落地**（2026-09-21）：新增 `netcfg.go`（接口层）+ `netcfg_ui.go`（控件与模型）+ `netcfg_pages.go`（页面与业务逻辑），新增 4 个页签「配置VXLAN的IP / 端口聚合 / 配置存储网 / 配置业务口」；协议由 4 份 HAR 逆向还原（详见 `docs/网络配置接口说明.md`）。

17. **离线验证体系**（可直接复用）：HAR 回放 mock 服务端（`mockserver/`，强制校验 CSRF + Cookie）→ 协议层 9 个 go test（含 4 个请求体与抓包逐字段一致）→ GUI 无头驱动截图（`shot.ps1`）。资产在 `.workbuddy/tmp/hciverify/`。
18. **界面布局修复**（踩坑后修）：HBox 拉伸控件（改固定宽度 + HSpacer）、VBox 摊高标签行/分组框、`GroupBox` 设固定高度导致内容与标题重叠（复选框组改用 Composite + 加粗标题）、`VSplitter` 默认 50/50 把编辑区压扁（改上固定 + 下自适应）。
19. **修复「最大化后标题栏按钮不可见」**（2026-09-21，多轮实测才定位准）：根因是 **walk 的 `FormBase.startLayout`（form.go:681）会在每次布局时把窗口撑到"布局最小尺寸"**（客户区 < min 就 `SetSizePixels`）。于是只要"布局最小尺寸"超过屏幕可用客户区，窗口就被撑得比屏幕还高，最大化时 Windows 把客户区扩成整窗、标题栏（含三个按钮）被内容覆盖。三条修法：
    ① **布局最小尺寸恒定且足够小**：新增 `reserveRows = 2`（`netcfg_ui.go`）—— 复选框区**固定预留行数、与条数无关**（`newCheckGroup` 构造时就套用 `applyReservedHeight`），否则数据一多（某节点 10 个物理口的复选框排到 3 行）最小尺寸就变大；同时把各页固定高度压下来（上区 190→120、差异框 130/120→68/60、`poolIPs` 92→64、存储网 `vsScroll` 200→140 且 `needH` 上限 170）。整窗布局最小尺寸：**1662x1519 → 1683x1367px**（< 最大化可用客户区 1436px）。
    ② **窗口初始尺寸按工作区反算并收敛**：新增 `applyWindowGeometry`（`min(布局最小尺寸, 工作区-16)`，用 `SetWindowPos` 设定）+ `moveWindowCentered`（只移动、带 `SWP_NOSIZE`，避免触发 walk 重新布局）；在 `Show()` 之后与 `Run()` 之后各幂等调用几次（walk 在 `Run()` 里还会撑一次）。
    ③ **"最大化"自己实现**：`toggleOwnMaximize` 拦截 `WM_SYSCOMMAND` 的 `SC_MAXIMIZE/SC_RESTORE`，把窗口铺满工作区而不用系统 zoom —— 彻底摆脱"布局最小尺寸 vs 屏幕尺寸"的耦合。
    实测（交付 exe，DPI=192 / 2560x1520 工作区）：启动窗口 2506x1477 在屏幕内；**系统 zoom** 与 **自绘最大化** 两条路径下标题栏均正常（`client=2560x1436@screen0,84`、自绘为 2560x1520），三个按钮可见可点。**注意：钳制 `PtMinTrackSize` 实测无效。**
20. **修复「端口聚合只显示 DOWN 口、UP 口不显示」**（2026-09-21）：原逻辑 `freePhyIfacesOf` 只保留"不在任何聚合口 + 无角色"的物理口，而现场每节点通常只剩 1 个空闲口（eth0，且 DOWN），UP 口（eth2~eth9）全是 channel1~4 的成员，于是界面上只剩 DOWN 可选。改为 `phyCandidatesOf` 返回**全部物理口**并标注占用者与链路状态，排序「空闲UP → 空闲DOWN → 占用UP → 占用DOWN」，新增「只选空闲口」按钮与 `bondOccupyWarning`（提交确认框对已被占用的口逐条告警，说明可能被移出原聚合口/角色）。mock 回放实测：成员口组列出 10 个物理口（空闲 1、被占用 9、其中 UP 8），UP 口全部可见可选。

## 6. 关键决策与原因

| 决策 | 原因 |
|---|---|
| 用 **Walk**（lxn/walk）而非 Fyne/Wails | 纯 Go、无 cgo/gcc 依赖，Windows 原生控件；Fyne 需 cgo+OpenGL 风险高 |
| **直接替换** CLI（不保留 -ui 开关） | 用户明确要求；CLI 版已备份在 backup/ |
| 修改网口**跳过 VerifyPassword** | 用户明确要求"不做验证，后续人工验证"；`VerifyPassword` 方法保留备用 |
| 异步用**子类化窗口过程 + PostMessage** | Walk 无官方后台→UI 线程调度 API；自定义 `App.WndProc` 覆盖**永远不会被调用**（`windowFromHandle(hwnd)` 返回注册的 MainWindow） |
| 表单布局用 **VBox+每行 HBox** | Walk 的 GridLayout 手动 API **不会自动流式排布**（需显式 SetRange），实测表单空白 |
| 硬件页 **ScrollView 直接当容器** | ScrollView 的 Children()/SetLayout() 已代理到内部 composite，再包一层会导致内容不渲染 |
| 刷新前**递归销毁控件树** | WidgetList.Clear() 只移除布局不销毁句柄；Dispose() 不递归子控件；否则刷新叠加"多个窗口" |
| 修改网口**全字段开放**（曾用 `allowedIface` 常量限定 ETH4，已移除） | 测试期约束已结束，全部网口与字段放开，由用户人工核对后提交 |
| 网口/链路模式用 **NewDropDownBox**（CBS_DROPDOWNLIST） | 不可编辑防止用户误删输入；DropDownList 样式点击输入框任意位置即展开下拉，无需点箭头 |
| 预览变更用**等宽对齐表格**（`formatChanges`/`dispWidth`） | diffText 使用 Consolas 等宽字体，中文按显示宽度 2 对齐，变更明细一目了然 |
| 编译加 `-ldflags "-H windowsgui"` | 取消运行黑框（已验证 PE 子系统=2） |
| GOPROXY=goproxy.cn | 官方 proxy.golang.org 网络超时不可达 |
| 4 类配置页**每个功能独立一个页签** | 与设备 Web 界面一一对应，用户心智一致；顶部共 10 个页签，窗口默认放宽到 1280×780 |
| 存储网/业务口用**两阶段提交**（先校验后写入） | 这两类变更影响存储心跳/业务连通，必须让用户在"看到差异 + 校验告警"之后再决定 |
| 聚合模式用**可编辑下拉**而非写死 | 抓包只见到 `lacp-layer34`，固件版本差异可能有别的模式；写死会直接做不了 |
| 业务口拓扑节点 ID 由**客户端生成 UUIDv4** | 抓包里该值为 v4 UUID，且紧随其后的任务日志出现"创建拓扑节点成功"，判定为客户端生成 |
| 复选框组**不用 GroupBox 包** | 实测给 GroupBox 设固定高度会与标题+边框布局冲突，内容重叠不可见 |

## 7. 代码、命令、配置与环境

- **环境**：Windows (win32)，Go **1.26.5 windows/amd64**，Shell 为 PowerShell 5.1（不支持 `&&`，用 `;` 或 `if ($?) {...}`；中文输出前先 `chcp 65001 > $null`）
- **编译命令**：
  ```powershell
  go mod tidy
  go build -ldflags "-H windowsgui" -o sangfor-ifaces-gui.exe .
  go vet ./...
  ```
- **rsrc 资源生成**：`rsrc -manifest app.manifest -o rsrc.syso -arch amd64`（工具：`go install github.com/akavel/rsrc@latest`，在 `%USERPROFILE%\go\bin`）
- **GOPROXY**：`go env -w GOPROXY=https://goproxy.cn,direct`
- **冒烟测试**：`Start-Process` 启动 exe → sleep 5s → `HasExited` 判断是否崩溃 → `Stop-Process`
- **窗口截图验证**：PowerShell + `Add-Type`（user32 `PrintWindow`/`SetForegroundWindow`）截 PNG → 识图确认（当前对话模型不支持直接看图，用 识图工具 兜底）
- **设备接口约定**（保持原样未改）：登录 6 步（/login 取 RSA 模数 → /vapi/json/access/srand → /secret → /privacy/check → /vapi/extjs/access/ticket 取 CSRFPreventionToken+LoginAuthCookie）；查询接口 /vapi/json/cluster/nodelist、/cluster/network/ifaces、/vapi/extjs/cluster/vms、/vapi/extjs/nodes/\<hostid\>/info；写接口 PUT /vapi/json/nodes/\<hostid\>/network/ifaces/\<iface\>（link_mode 自动协商值按网卡推导，不写死 6）
- **登录默认值**：设备地址默认 `192.168.1.100`（可在输入框改）；会话缓存自动预填 host/user/password
- **事件消息**：`msgUIEvent = win.WM_APP + 100`；事件类型：login_ok/login_err/err/nodes_done/ifaces_done/vms_done/hw_done/setiface_ifaces_done/setiface_reload_done/setiface_task_done

## 8. 遇到的问题与已尝试方案

1. **登录卡在"正在登录"**（严重）：自定义 `App.WndProc` 不被 Walk 消息循环调用（windowFromHandle 返回注册的 MainWindow）→ 方案无效 → 改**子类化窗口过程**有效（probe 验证 MSG RECEIVED OK）。
2. **编译报错**：备份 .go 文件重复定义（移到 backup/ 子目录解决）；`walk.NewTableColumn` 不存在（改用 `NewTableViewColumn()+SetTitle/SetWidth`）；`walk.NewFont` 签名是 `(family, pointSize, style)`；菜单需 `Menu.Actions().AddMenu()` + `walk.NewAction()`。
3. **硬件信息不可读**：文本格式 → 结构化 GroupBox 卡片（有效）。
4. **修改网口看不到输入框**：GridLayout 标签/输入框错位（先建框后建标签）→ 交替添加仍无效 → 根因是 **GridLayout 不自动排布** → 换 VBox+HBox 行（有效，截屏确认）。
5. **硬件信息空白**：ScrollView 多包 inner → 直接用 ScrollView 当容器（有效，截屏确认）。
6. **刷新硬件信息出现多个窗口**：Clear 不销毁句柄 + Dispose 不递归 → `disposeWidgetTree` 递归销毁（已修复，待用户实测确认）。
7. **官方 Go 代理超时**：`dial tcp 142.250.69.177:443 ... failed` → 换 goproxy.cn（有效）。
8. **探针 TTM_ADDTOOL failed panic**：子目录无 manifest 资源 → 复制 rsrc.syso 解决；后续 nil deref panic 因探针未 SetLayout → 补 `mw.SetLayout(NewVBoxLayout())` 解决。

## 11. 重要约束、偏好和注意事项

- **Walk 已知坑**（勿重犯）：GridLayout 需 SetRange 不自动排布；ScrollView 不能包 inner；Clear() 不销毁句柄、Dispose() 不递归（重建前必须递归 Dispose）；不要自定义覆盖 WndProc（用子类化）；NewTableColumn/NewFont/菜单 API 用法见上文。
- 修改网口是**高危写操作**，确认对话框必须保留；所有网口与字段均已放开，提交前人工核对变更明细。
- 用户偏好：**中文界面与中文沟通**；桌面窗口程序；无黑框；"直接替换"CLI 的精神（CLI 只留备份，不混入主程序）。
- 环境：PowerShell 5.1 无 `&&`；命令前先 `chcp 65001`；Windows 路径反斜杠。
- 会话/输入缓存文件会生成在**可执行文件同目录**（.sangfor-session.json 含密码，.sangfor-lastinput.json 记录输入）。
- 设备是深信服超融合（自签名证书 + 仅 TLS1.2 RSA 套件，`InsecureSkipVerify` 已设置，勿改动）。
- 当前对话模型**不能直接看图**，需要识图时用 `识图工具`。
- **4 类新写操作全部未在真机验证**：协议按 HAR 逐字段还原并做了一致性测试，但"设备是否接受"必须真机确认；首次使用请先只读核对，再选低风险项（空闲聚合口）试手。
- **窗口尺寸/最大化相关（本轮实测结论，新增页面务必遵守）**：① **只要客户区小于"布局最小尺寸"，walk 就会在 `startLayout` 里把窗口撑大**（`form.go:681`）—— 所以"页面里随数据变高的控件"（复选框列表、明细行）必须**固定预留高度**，否则窗口尺寸不可控；整窗布局最小尺寸要小于"最大化后可用客户区高度"（本环境 1436px）。② **钳制 `PtMinTrackSize` 无效**（实测）。③ walk 的 `SetSize` 是 96DPI 逻辑单位，200% 缩放下会翻倍超出屏幕；`FormBase.SetBoundsPixels` 也会被 `startLayout` 再撑一次 —— 窗口尺寸/位置一律用 `SetWindowPos` 自己设（摆位置带 `SWP_NOSIZE`）。④ 想彻底稳，就**自己实现最大化**（拦截 `SC_MAXIMIZE/SC_RESTORE` 铺满工作区），不要依赖系统 zoom。
- **PowerShell 脚本必须是"单个" UTF-8 BOM**：无 BOM 会按 ANSI 解码导致乱码报错；**两个 BOM** 会报 `无法将“#”项识别为 cmdlet` —— 转换前先用二进制方式去掉已有 BOM 再写。
- **跨进程 GUI 自动化的两个坑**（做验证时会踩）：① 跨进程发 `TCM_GETITEMRECT` 等"带指针"的窗口消息，会让 walk 的 tab 处理函数解引用无效指针 → **0xc0000005 崩溃**，切页签只能用"带坐标的鼠标消息"；② 用 Windows 自带的脚本宿主读 **UTF-8 无 BOM** 的脚本文件会按 ANSI 解码，导致引号错位、语法报错，脚本必须存成 **UTF-8 with BOM**。
