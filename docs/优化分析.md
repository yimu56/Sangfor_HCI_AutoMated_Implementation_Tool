## 三、已修复的缺陷（已合入 `main.go` 并重新编译）

### 修复 1：`truncate` 按字节截断 → 中文乱码风险（真实潜在 bug）
原实现 `return s[:n] + "..."` 按**字节**切片。当 `s` 含中文且 `n` 落在某个 UTF-8 字符中间时，会切出非法 UTF-8 序列，导致日志/错误信息/虚拟机名出现乱码甚至渲染异常。
`truncate` 被用在：API 错误回显（`callAPI`/`Login`/`VerifyPassword`）、虚拟机名截断（`vmModel.Value`）、等多处。

```go
// 修复后：按字符（rune）计数
func truncate(s string, n int) string {
	if r := []rune(s); len(r) <= n {
		return s
	} else {
		return string(r[:n]) + "..."
	}
}
```

### 修复 2：修改网口失败时仍记住「上次输入」（行为正确性）
原 `onSubmit` 中，即使任务报错（只要返回了非空 message），仍会把这次输入写入 `.sangfor-lastinput.json` 作为下次默认值——等于把**失败/未生效**的配置当成默认值代入下次，容易误导。

修复后：**仅当任务成功（`err == nil`）才记录上次输入**；任何失败（含超时）都不再记录。

> 验证：`go vet` 与 `go build` 在修改后均通过，已用原命令重建 `sangfor-ifaces-gui.exe`。

## 四、建议的后续优化（本次未改，需评估/实测）

| 优先级 | 项 | 说明 | 风险/注意 |
|---|---|---|---|
| 中 | 复用节点列表缓存 | `fetchIfacesAll`/`fetchHW` 每次刷新都重新 `GetNodeList()`（2 次额外 HTTP）。可复用登录时拉到的 `a.nodes` | ⚠️ `a.nodes` 只在 UI 线程写；若改为后台 goroutine 直接读会引入 **data race**。需加 `sync.Mutex` 或把节点切片作为事件数据传递，不能随意改 |
| 中 | 会话密码加密存储 | `.sangfor-session.json` 明文存密码（0600）。可改为 AES 用设备地址派生密钥加密，或改为「不保存密码、仅保存 token/cookie」 | 低，可选 |
| 中 | 评估恢复密码二次验证 | 修改网口当前跳过 `VerifyPassword`（用户明确要求）。正式使用前建议恢复 | 需设备侧确认 |
| 低 | 清理 `Logout()` 死代码 | 定义但从未调用。可挂到「退出」菜单或窗口关闭时登出，或直接删除 | 无 |
| 低 | 硬件信息页刷新残留实测 | `disposeWidgetTree` 已修复，但需真机连点刷新确认无叠加窗口 | 需真机 |
| 低 | `dispWidth` 对齐精度 | 用 `r > 0x2E7F` 粗略判定宽字符（CJK 够用，个别全角符号可能算错）。如需百分百精确可用 `golang.org/x/text/width` | 低，当前足够 |
