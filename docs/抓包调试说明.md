# 调试抓包（HAR）说明

一个**可配置的调试功能**：打开开关后，程序会把**每一次网络请求**（登录握手、所有 vapi 查询与写操作）
记录成标准 **HAR 1.2** 文件，方便排查问题时对照报文。
**默认关闭**，且开关只存在于配置文件里（改完重启生效），不会误开。

---

## 1. 开关项名称

| 配置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `debug.capture_har` | bool | **`false`（关闭）** | **抓包总开关**。`true` = 对所有网络请求抓包 |
| `debug.har_dir` | string | `""`（空） | HAR 存放目录；**留空表示用默认目录**（见下） |
| `debug.har_max_entries_per_file` | int | `500` | 单个 HAR 文件最多记录多少条请求；超出后**滚动出下一个分片文件** |
| `debug.har_max_body_kb` | int | `2048` | 单条请求体/响应体最多保留多少 KB；超出会截断并在 HAR 里标记 `_truncated` |
| `debug.har_mask_secrets` | bool | **`true`** | 是否对 Cookie / CSRF 令牌 / 口令 / ticket 等**敏感值脱敏**（强烈建议保持 `true`） |

**开关项全名（点号路径）**：`debug.capture_har`

---

## 2. 配置文件位置

```
<程序所在目录>\.sangfor-config.json
```

- 例：程序在 `C:\Tools\HCI Tool\sangfor-ifaces-gui.exe` → 配置文件在
  `C:\Tools\HCI Tool\.sangfor-config.json`
- **首次运行时自动生成**（内容为默认值，即抓包关闭），并带 `_说明` 字段解释各选项
- 配置文件解析失败时程序**不会覆盖它**，只按默认值运行（抓包关闭）
- 也可以从菜单 **调试(&D) → 打开配置文件(&C)** 直接打开

生成的默认内容：

```json
{
  "_说明": "……（说明文字）……",
  "debug": {
    "capture_har": false,
    "har_dir": "",
    "har_max_entries_per_file": 500,
    "har_max_body_kb": 2048,
    "har_mask_secrets": true
  }
}
```

**打开抓包**：把 `capture_har` 改成 `true` → 保存 → **重启程序**。

---

## 3. 存放路径

```
<程序所在目录>\har\<yyyy-MM-dd>\<文件>
```

- 即：默认在程序同目录下新建 `har` 子目录，再按**当天日期**分目录存放
- 例：`C:\Tools\HCI Tool\har\2026-09-21\`
- 若要放到别处，把 `debug.har_dir` 设成绝对路径即可（例：`"D:\\capture\\hci"`），
  此时目录结构为 `<har_dir>\<yyyy-MM-dd>\<文件>`
- 程序内可从菜单 **调试(&D) → 打开抓包目录(&H)** 直接打开这个目录

---

## 4. 文件命名规则

```
sangfor-<设备地址>-<yyyyMMdd-HHmmss>-p<进程号>.har
```

| 片段 | 含义 | 示例 |
|---|---|---|
| `sangfor-` | 固定前缀 | `sangfor-` |
| `<设备地址>` | 本次登录的设备地址（冒号替换成下划线） | `192.168.131.179`、`127.0.0.1_8443` |
| `<yyyyMMdd-HHmmss>` | 程序本次启动时间 | `20260921-231103` |
| `p<进程号>` | 进程 ID（同一秒多次启动也能区分） | `p2848` |
| `.har` | 标准 HAR 1.2 扩展名 | |

**分片（滚动）规则**：同一个会话内条目数超过 `har_max_entries_per_file` 时，
自动开始写下一个文件，在进程号后追加序号：

```
sangfor-192.168.131.179-20260921-231103-p2848.har        ← 第 1 个（无序号）
sangfor-192.168.131.179-20260921-231103-p2848-2.har      ← 第 2 个
sangfor-192.168.131.179-20260921-231103-p2848-3.har      ← 第 3 个
```

也就是说：**一次程序运行 = 一组同名文件**（时间戳/进程号相同，只有序号不同），
查问题时按时间戳就能定位到"哪一次运行"。

## 5. 抓包范围与形态

- **范围**：所有 HTTP 请求都记录 —— 登录握手（`GET /login` → `access/srand` → `access/secret`
  → `access/privacy/check` → `extjs/access/ticket`）+ 全部业务接口（节点/网口/VXLAN/虚拟机/硬件、
  以及 4 类网络配置的读、校验、写、任务轮询、回读）；请求失败（连不上/超时）也会留一条，
  在 `comment` 里写明失败原因（`status` 为 0）。
- **形态**：标准 **HAR 1.2**，包含 `request`（方法/URL/头/表单或 JSON body）、
  `response`（状态码/头/正文）、`timings`、`startedDateTime` 等字段，
  可直接用 **Chrome DevTools（Network 面板 → Import HAR）**、Fiddler、Charles 打开回放。
- **写入时机**：每记录一条就**原子落盘**（先写 `.tmp` 再改名），程序被强杀也不会丢已抓到的报文。

---

## 6. 隐私与安全（重要）

- 默认 `har_mask_secrets = true`，以下内容会被替换成 `<已脱敏>`：
  - 请求/响应头：`Cookie`、`Set-Cookie`、`CSRFPreventionToken`、`Authorization`
  - 表单/查询串/JSON 里字段名含 `password` / `pwd` / `secret` / `ticket` / `token` / `cookie` 的值
    （例如 `password=...`、`"csrf_token":"..."`）
- **即便如此，HAR 仍属于敏感数据**（含内网地址、拓扑、节点名等）：请勿外发、勿上传工单系统。
- 仓库已把 `.sangfor-config.json`、`har/`、`*.har` 加进 `.gitignore`，正常不会误提交。
- 排障结束后建议**关掉开关**并把 `har` 目录里的文件删掉。

---

## 7. 界面入口

菜单 **调试(&D)**：

| 菜单项 | 作用 |
|---|---|
| `抓包：已开启 → <目录>` / `抓包：关闭（配置文件 debug.capture_har=false）` | 只读状态提示（禁用项） |
| `打开抓包目录(&H)` | 用资源管理器打开存放目录（仅在开启时可用） |
| `打开配置文件(&C)` | 打开 `.sangfor-config.json`，改完**重启程序**生效 |

---

## 8. 验证方式（本功能自带）

- 单元测试：`go test -run TestHar -v .`（覆盖默认关闭 / 配置读写 / 脱敏 / 目录与命名规则 /
  分片滚动 / HAR 结构合法性 / 失败请求留痕）
- 端到端：对着 mock 设备跑一遍登录 + 全量刷新，检查生成的 HAR 里接口覆盖与脱敏效果
